## 1. TypeScript — `tsconfig.json` and `strict`

| | TypeScript |
|---|---|
| `strict` — what it is (umbrella flag) | One switch that turns on six flags: `strictNullChecks`, `noImplicitAny`, `strictFunctionTypes`, `strictPropertyInitialization`, `strictBindCallApply`, `useUnknownInCatchVariables` (current TS also includes `noImplicitThis`) |
| `noImplicitAny` — error it gives + fix | `TS7006` Parameter implicitly has an `any` type. Fix: `function double(x: number)` |
| `strictNullChecks` — error it gives + fix | `TS18047` `el` is possibly `null`. Fix: `if (el !== null) el.innerHTML = ""` |
| `strictPropertyInitialization` | `TS2564` field has no initializer. Fix: assign it in the constructor, give a default, or `constructor(public name: string) {}` |
| `useUnknownInCatchVariables` | `TS18046` `e` is `unknown`. Fix: `if (e instanceof Error) e.message` |
| `strictBindCallApply` | `TS2345` wrong argument type. Fix: `greet.call(null, "hi")`, `greet.apply(null, ["hi"])` |
| `noImplicitThis` | `TS2683` `this` implicitly `any` in a nested regular function. Fix: arrow function, which inherits `this` |
| `noUncheckedIndexedAccess` (not in `strict`) | `arr[0]` becomes `T \| undefined`. Fix: `arr[0] ?? 0`, or type it `number \| undefined`, or narrow |
| `target` / `module` | `target`: JS version to output (`ES2022` keeps `?.`, `??`). `module`: import/export style (`ESNext` keeps `import`) |
| `include` / `exclude` | Which files are checked. `include: ["src"]`, `exclude: ["node_modules", "dist"]` |
| `noEmit` — why `tsc --noEmit` for type-checking only | Checks types and writes no JS. Used with Vite, which builds the JS itself |
| Trap | `strict` off accepts all seven demo mistakes (`exit 0`). `noUncheckedIndexedAccess` is not part of `strict`. `x!` / `name!: string` silences an error without fixing it |

## 2. TypeScript — functions recall (§7)

| | TypeScript |
|---|---|
| Param + return annotation | `function add(a: number, b: number): number`. Parameters need types; the return type can be inferred but writing it makes the compiler check it |
| Optional vs default param | Optional `level?: "warn" \| "error"` has type `... \| undefined`, so check before use. Default `greeting = "Hello"` is inferred, never `undefined` inside. Both go after required params |
| Rest param typed | `...nums: number[]`. Collects the remaining arguments into an array, must be last |
| Overload — signatures vs implementation | Signatures are the declarations callers see, with no body. One implementation below handles all of them and is hidden. Use only when the return type depends on the arguments |
| `this` parameter | A fake first parameter, `this: HTMLButtonElement`. Declares what `this` must be, erased at compile time. Not allowed on arrow functions |
| Union param vs options object | Union: one value of several types (`id: string \| number`). Options object: one parameter bundling many optional settings. Prefer it for three or more parameters |
| Trap | Optional param type includes `undefined`. `void` callback type can still return a value. A method copied to a variable loses `this` (`const c = counter.inc; c()`) |

## 2b. `this`, `call`, `apply`, `bind`

| | JavaScript / TypeScript |
|---|---|
| Who decides `this` | The call site, not where the function is stored |
| `obj.fn()` | `this = obj`, for that call only |
| `const f = obj.fn; f()` | `this` lost. Strict mode: `TypeError`. Sloppy mode: `this = globalThis`, so `NaN` and a stray global |
| Arrow function | No `this` of its own, uses the surrounding one |
| `fn.call(obj, a, b)` | Runs now, `this = obj`, arguments listed |
| `fn.apply(obj, [a, b])` | Runs now, `this = obj`, arguments in an array |
| `fn.bind(obj)` | Returns a new function with `this` fixed to `obj`. Runs later |
| First argument | Always `this`. Pass `null` only when the function doesn't use `this` |
| Trap | `setTimeout(counter.inc, 100)` passes a detached method. Use `.bind(counter)` or `() => counter.inc()` |

## 3. Python — tuples, sets, dicts, next to JS and TS

| | Python | JavaScript | TypeScript |
|---|---|---|---|
| Fixed-size ordered group | tuple | no tuple, use an array `[a, b]` | tuple type `[string, number]` |
| Create / unpack | `t = (1, 2)`, `a, b = t` | `const [a, b] = arr` (destructuring) | `const t: [string, number] = ["x", 1]` |
| Unique values + membership | `set`, `x in s` | `Set`, `s.has(x)` | `Set<T>` |
| Union / intersection / difference | `a \| b`, `a & b`, `a - b` | `new Set([...a, ...b])`, `.filter(x => b.has(x))`, `.filter(x => !b.has(x))` | same as JS |
| Key-value store | dict | `Map` / object | `Record<K,V>` / `Map<K,V>` |
| Safe read of a missing key | `d.get(k, default)` | `m.get(k) ?? default` | same, but `m.get(k)` is `V \| undefined` |
| Count word frequency | `d[w] = d.get(w, 0) + 1` | `m.set(w, (m.get(w) ?? 0) + 1)` | `Map<string, number>`, same line |
| Dedupe a list | `list(set(lst))` | `[...new Set(arr)]` | same as JS |
| Trap | `{}` is an empty dict, not a set (use `set()`). One-item tuple needs a comma: `(1,)` | Object keys become strings, `Map` keeps their type. `Set` compares objects by reference | Tuples exist only at compile time |

## 4. 3Sum — sorted two-pointer inside a loop

| | |
|---|---|
| Why sort first | Sorted order lets the pointer sum tell you which pointer to move, and puts duplicates next to each other |
| Outer loop: what `i` fixes | The first number of the triplet. `j = i + 1` so no element is reused and no earlier combination is repeated |
| Inner loop: how it reuses Two Sum II | With `i` fixed, `j` and `k` run Two Sum II on the rest with target `-nums[i]`. Sum too big: `k--`. Too small: `j++` |
| Where duplicates are skipped (two places) | `i`: `i > 0 && nums[i] === nums[i-1]` then `continue`. `j`: after recording a hit, `while (nums[j] === nums[j-1] && j < k) j++` |
| Early exit when `nums[i] > 0` | `break`. The smallest number is positive, so no sum can reach 0 |
| Time complexity | O(n²): n choices for `i`, one sweep of up to n steps each. Extra space O(1) apart from the output |
| Trap | Skipping duplicates at only one level, or before recording a hit. `nums.sort()` without a comparator sorts as strings. Pushing `[a + b + c]` instead of `[a, b, c]`. `nums[i-1]` at `i = 0` |
